# 🍽️ Food Orders ELT Pipeline

A batch-based **Extract, Load, Transform (ELT)** data engineering pipeline built using Python, Pandas, and MySQL. The project demonstrates raw data ingestion, batch processing, data transformation, validation, and analytics-ready data loading.

## 📌 Project Overview

This project implements an ELT workflow for food order data. The original CSV dataset is first loaded into a raw MySQL database without applying transformations. The raw records are then retrieved in batches, processed using Pandas, validated for data quality, and loaded into a separate analytics database.

The pipeline also identifies duplicate records, handles missing or invalid values, derives business metrics, and generates validation reports.

## 🎯 Objectives

- Implement a batch-based ELT pipeline using Python and MySQL.
- Preserve the original source data in a raw database.
- Retrieve and process records in manageable batches.
- Transform raw data into a structured, analytics-ready format.
- Validate records and identify duplicate or invalid data.
- Separate raw storage from the analytics layer.
- Generate output files and reports for data quality monitoring.
- Perform business analysis using SQL queries.

## 🚀 Installation and Setup

### 1. Clone the repository

```bash
git clone https://github.com/Swetha-atluri/food_orders_ELT_Pipeline.git
cd food_orders_ELT_Pipeline/food_orders_elt_pipeline
```

### 2. Create a virtual environment

```bash
python -m venv .venv
```

Activate it on Windows:

```powershell
.venv\Scripts\Activate.ps1
```

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

### 4. Configure environment variables

Copy `.env.example` to a new file named `.env` and enter your local MySQL connection details.

Example configuration:

```dotenv
MYSQL_HOST=localhost
MYSQL_PORT=3306
MYSQL_USER=your_mysql_username
MYSQL_PASSWORD=your_mysql_password
```

Use the exact variable names expected by `config.py`. Never commit the actual `.env` file or real credentials to GitHub.

### 5. Start MySQL Server

Ensure that MySQL is running and that the configured user has permission to create databases and tables.

### 6. Run the pipeline

From the project directory, execute:

```bash
python elt_batch_pipeline.py
```

The pipeline coordinates the extraction, raw loading, batch retrieval, transformation, validation, and analytics loading steps.

## 🔄 Pipeline Workflow

### 1. Extract

- Reads the source CSV using Pandas.
- Processes the dataset in batches rather than loading all records into memory at once.
- Preserves source values for raw ingestion.

### 2. Load Raw Data

- Stores source records in the raw MySQL database.
- Uses raw storage to preserve the original data before transformation.
- Inserts records in batches.

### 3. Retrieve

- Retrieves raw records from MySQL in manageable batches.
- Provides data to the transformation stage.

### 4. Transform

- Converts date and time fields into appropriate data types.
- Converts numeric and financial fields.
- Derives delivery duration and net revenue where the required source values are available.
- Identifies exact duplicate source rows.

### 5. Validate

- Checks required timestamps and delivery duration.
- Identifies invalid records.
- Checks transformation rules and reports data quality results.

### 6. Load Analytics Data

- Loads valid transformed records into a separate analytics database.
- Uses structured columns suitable for SQL-based analysis.

### 7. Generate Outputs

Depending on the pipeline execution, the following files are generated:

- `transformed_valid_records.csv` — valid transformed records.
- `rejected_records.csv` — rejected records and rejection reasons.
- `validation_report.json` — validation and execution summary.

- Identification of useful business patterns.

Run the queries against the analytics database after the pipeline has completed successfully.

## 🧪 Data Quality and Validation

The pipeline includes checks designed to improve the reliability of analytics data:

- Required timestamp validation.
- Delivery duration validation.
- Duplicate record detection.
- Numeric and financial data conversion.
- Validation of derived metrics.
- Rejected-record tracking.
- Execution and validation reporting.

Missing financial inputs are handled according to the transformation rules in the source code; records with unavailable required financial values may have a null derived revenue rather than an invented value.

## 🔐 Configuration and Security

- Database credentials are supplied through environment variables.
- `.env` is excluded through `.gitignore`.
- `.env.example` documents the required configuration without storing real secrets.
- Raw and analytics databases are kept separate.

Never upload database passwords, API keys, or other sensitive credentials to a public repository.
